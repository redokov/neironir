# Агентская документация — обзор

Этот каталог — набор пошаговых спецификаций для агентов-исполнителей. Каждый файл описывает **одну фазу** реализации: входные условия, файлы, которые нужно создать/изменить, критерии приёмки, контрольные команды.

Фазы идут последовательно. Перед стартом следующей фазы предыдущая должна быть зелёной (тесты + линт).

## Глобальные правила для агентов

1. **Не выходить за границы фазы.** Если нужно что-то сверх спецификации — пометить в отчёте как «вне scope» и дождаться следующей фазы.
2. **Только заявленные зависимости.** Никаких новых библиотек без обоснования. Если нужна — добавить в `pyproject.toml` и в отчёт.
3. **Код — на русском?** Нет, весь код и сообщения коммитов — на английском. UI-тексты (кнопки, лейблы) — на русском.
4. **Стиль:**
   - Форматирование: `ruff format`.
   - Линт: `ruff check` (правила `E,F,I,UP,B,SIM`).
   - Типы: `mypy --strict` (на момент фазы 3+).
5. **Тесты:** каждая фаза, которая пишет код, добавляет хотя бы один тест на новую логику.
6. **Коммиты:** conventional commits (`feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`).
7. **Не пушить.** Агент коммитит локально, пользователь пушит сам (или по явной команде).
8. **Один PR / одна фаза.** Можно делать несколько коммитов, но в рамках одной фазы.

## Отчёт фазы

Каждый агент в конце работы возвращает:

- Что сделано (списком файлов).
- Какие критерии приёмки выполнены.
- Что не сделано и почему.
- Команды, которые нужно выполнить вручную (если есть).
- Любые развилки, требующие решения пользователя.
