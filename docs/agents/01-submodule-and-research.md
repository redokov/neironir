# Фаза 1. Submodule + research privacy-filter

## Цель

1. Подключить `openai/privacy-filter` как git submodule в `privacy-filter/`.
2. Исследовать его CLI/интерфейсы и зафиксировать **контракт вызова** для нашего адаптера.
3. Решить, как именно адаптер будет дёргать модель, и зафиксировать решение в [03-backend.md](./03-backend.md).

## Входные условия

- Фаза 0 завершена, есть `pyproject.toml` и `backend/neironir/`.
- Доступ в интернет для `git submodule add`.

## Что делаем

### 1. Добавить submodule

Из корня репозитория:

```bash
git submodule add git@github.com:openai/privacy-filter.git privacy-filter
git submodule update --init --recursive
```

Закоммитить:

```
chore: add privacy-filter as git submodule
```

### 2. Исследование

Прочитать `privacy-filter/README.md`, `privacy-filter/pyproject.toml` (если есть), `privacy-filter/setup.py` (если есть), `privacy-filter/privacy_filter/...` или аналогичный путь с исходниками. Понять:

- Есть ли CLI? Какая команда?
- Есть ли Python API (импорт пакета)? Какие функции/классы?
- В каком формате модель принимает текст на вход и отдаёт аннотации на выход?
  - JSON со списком сущностей? Разметка в тексте? Что-то ещё?
- Какие 8 типов сущностей она отдаёт? **Внимание:** в [architecture.md](../architecture.md) зафиксирован список из 8 типов, который должен совпасть с тем, что реально отдаёт модель. Если есть расхождения — **сообщить пользователю**, не править список самовольно.
- Какие зависимости нужны (torch, transformers, …)?

### 3. Артефакт исследования

Создать `docs/agents/privacy-filter-research.md` со следующей структурой:

- **Источник истины:** коммит/тег submodule, на котором зафиксировано исследование.
- **Способ запуска:** CLI / Python API / что-то ещё.
- **Команда/вызов:** точная команда или сигнатура.
- **Входной формат:** пример.
- **Выходной формат:** пример (JSON-схема или фрагмент).
- **Список типов сущностей:** какие строки отдаёт модель. Совпадают ли с архитектурой — **явно** написать «совпадают» или «расхождение: …».
- **Зависимости:** список пакетов с версиями.
- **Замечания и риски:** что непонятно, что нужно уточнить у пользователя.

### 4. Принятое решение по интеграции

Зафиксировать в `docs/agents/03-backend.md` (фаза 3) **в разделе «Интеграция с privacy-filter»**:

- **Решение по умолчанию (если модель даёт CLI):**
  - запускаем `python -m privacy_filter ...` через `asyncio.create_subprocess_exec`,
  - текст передаём через stdin или временный файл (что подтверждено исследованием),
  - JSON с сущностями получаем через stdout,
  - ограничиваем по таймауту `NEIRONIR_PRIVACY_FILTER_TIMEOUT`.
- **Если модель даёт только Python API:**
  - импортируем пакет, вызываем функцию аннотирования синхронно (в `run_in_executor`, чтобы не блокировать event loop),
  - требования к зависимостям (torch/transformers) добавляем в опциональную группу `pyproject.toml` (`[dependency-groups] ml` или `[project.optional-dependencies.ml]`) — **не** в основные runtime-зависимости, чтобы обычный запуск backend был лёгким.

> Решение **не принимается в этой фазе автоматически**, если формат неочевиден. Агент обязан запросить подтверждение пользователя.
