## [Unreleased]

### Изменено (ломающее)

- **Токен задачи больше не принимается из URL (спек 008).** Запасная ветка
  `?access_token=` на `/download` удалена: токен авторизует запрос только
  из заголовка `X-Job-Token`. Скачивание из веб-интерфейса переведено на
  `fetch` с заголовком (`Blob`/`URL.createObjectURL`), так что токен не
  оседает в истории браузера, access-логах и Referer. Старые открытые
  ссылки вида `/download?access_token=...` перестают работать (проект
  до версии 1.0, ломающее изменение приемлемо).

## [0.2.0] — 2026-11-09

### Добавлено

- **Programmatic (M2M) API (спек 005).** Доступ к пайплайну анонимизации без
  веб-интерфейса: статические Bearer-ключи из `NEIRONIR_API_KEYS` (через
  запятую; пустое значение — M2M отключён, интерфейс работает как раньше),
  те же эндпоинты `/api/v1/documents`: загрузка → опрос статуса → скачивание.
  Скачивание по умолчанию отдаёт бинарный файл; при `Accept: application/json` —
  JSON `DownloadResultResponse` с base64-контентом того же файла.
  Запросы с заголовком `Authorization` всегда проходят проверку ключа
  (отказ — `401` `invalid_api_key` + `WWW-Authenticate: Bearer`, session-cookie
  не подменяет ключ); без заголовка — только для loopback-клиентов
  (см. ужесточение ниже).
  Ключи сравниваются в constant-time и не логируются. См. [docs/api.md](./docs/api.md),
  раздел «Machine-to-machine API».

- **Ужесточение безопасности и приватности (спека 007, T1–T7).**
  - **T1 — отказоустойчивая к закрытию авторизация документов.** Загрузка без
    заголовка `Authorization` разрешена только локальным (loopback) клиентам;
    внешним без валидного Bearer-ключа — `401`; присланный невалидный Bearer
    отклоняется всегда, даже при валидной сессионной куке.
  - **T2 — ограниченный объём загрузки.** Учитываются все входящие блоки
    запроса, а не только Content-Length; сверх лимита — стабильный `413`,
    каталог задачи не создаётся.
  - **T3 — персональный токен задачи (`X-Job-Token`).** Одноразовый
    opaque-токен выдаётся только в ответе `202`; в `job.json` хранится
    лишь SHA-256-digest. Все запросы к задаче требуют заголовок;
    неверный/отсутствующий токен и legacy-задача дают неразличимый
    `404` `job_not_found`.
  - **T4 — отзыв админ-сессий.** В подписанную сессию добавлен уникальный
    `jti`; logout отзывает сессию до истечения срока жизни (ограниченный
    реестр в памяти процесса).
  - **T5 — защита от ReDoS в динамических правилах.** Опасные регулярные
    выражения (вложенные квантификаторы, обратные ссылки, длина более 200)
    отклоняются стабильным кодом `unsafe_regex` (`422`) и пропускаются
    при загрузке сохранённых правил.
  - **T6 — ограниченная JSON-выдача и нормализация спанов.** Скачивание
    в JSON с base64-контентом ограничено
    `NEIRONIR_MAX_JSON_DOWNLOAD_SIZE` (по умолчанию 5 МиБ, сверх — `413`);
    некорректные и перекрывающиеся спаны отбрасываются до рендеринга.
  - **T7 — документация и регрессионный шлюз.** `docs/api.md`,
    `.env.example`, `README.md` и `docs/architecture.md` синхронизированы
    с новыми контрактами.

## [0.1.0] — 2025-07-16

Первый тегированный релиз: стабилизация после Фазы 2 по результатам
углублённого код-ревью (см. `code-review-report.md`).

### Исправлено

- **Админка: порядок документов с фидбеком.** Список
  `GET /api/v1/admin/documents` сортировался по имени каталога (UUID), а не
  по дате, и `limit` отрезал произвольное подмножество. Теперь записи
  сортируются по `finished_at` (с fallback на `created_at`) по убыванию,
  лимит применяется после сортировки — сверху всегда самые свежие правки.
- **Runtime-таймаут OPF применяется без рестарта.** `PUT /api/v1/admin/settings`
  раньше писал значение в файл и в мёртвый атрибут настроек, а живой клиент
  продолжал работать со старым таймаутом до перезапуска. Теперь эндпоинт
  обновляет синглтон privacy-клиента на лету (`update_privacy_timeout`);
  тот же override учитывается и при запуске дообучения.
- **Open redirect в `GET /login`.** Параметр `?next=` не проверялся для
  уже аутентифицированного пользователя. Общий `_safe_next_url()` теперь
  отсекает абсолютные URL, protocol-relative (`//host`) и backslash-трюки
  в обоих обработчиках логина.
- **Валидация ручных правил.** `POST /api/v1/rules` возвращает 422 на
  неизвестный `entity_type`, и добавленное вручную правило сразу
  hot-reload'ится в детектор (как при approve).
- **Целостность файлов.** `counters.json` при apply-feedback пишется
  атомарно; битый `job.json` в деталях документа отдаёт корректный
  500-конверт вместо traceback.

### Изменено

- Токенизация `privacy_filter_cmd` унифицирована в
  `neironir.config.parse_opf_cmd()` (shlex, защита Windows-путей и
  кавычек) и используется и в annotation-, и в training-путях.

### Тесты

- +30 новых тестов: сортировка/лимит документов, `parse_opf_cmd`,
  `update_privacy_timeout`, runtime-settings API, open-redirect кейсы,
  API ручных правил. Общее покрытие — 85% (гейт CI: 70%).
