# Product Steering

## Product Vision

`neironir` — локальный веб-сервис для удаления персональных данных (PII) из текстовых документов (`.md`, `.docx`) перед загрузкой во внешние нейросети. Сервис работает через локально развёрнутую модель [privacy-filter](https://github.com/openai/privacy-filter.git) и заменяет сущности 8 типов на стабильные плейсхолдеры (`<PRIVATE_PERSON1>`, `<ACCOUNT_NUMBER1>` и т.д.). Преобразование **однонаправленное**: карта замен не хранится, обратной замены нет.

## Target Users / Personas

- **Автор документа, передающий его во внешнюю нейросеть** — хочет загрузить файл в LLM, не раскрывая свои/чужие PII, контакты, номера счетов, даты, адреса.
- **Юрист / аналитик / журналист / разработчик** — работает с длинными `.md` и `.docx` документами (договоры, ТЗ, заметки, отчёты) и нуждается в быстрой локальной очистке без отправки контента в чужие сервисы.
- **Администратор системы** (позднее — после фазы Admin UI) — управляет накопленными аннотациями, контролирует дообучение модели, утверждает предложенные правила.

## Value Proposition

- **Локальность:** PII никогда не покидают машину пользователя; модель работает на его железе.
- **Однонаправленность:** даже при компрометации сервиса восстановить исходные данные нельзя — карты замен не существует.
- **Поддержка родного формата:** пользователь получает `.md`/`.docx` той же структуры, не plain-text.
- **Прозрачность:** понятный набор из 8 типов сущностей и стабильная сквозная нумерация плейсхолдеров в пределах документа.
- **Гибкость развёртывания:** `mock`-режим для разработки и CI, `subprocess`-режим для production с реальной моделью `opf`.

## Product Boundaries

### In Scope (MVP+)

- Загрузка `.md` и `.docx` через веб-интерфейс.
- Очистка 8 типов PII: имя, адрес, email, телефон, дата, URL, номер счёта, секрет.
- Выдача очищенного файла того же формата.
- Опциональная конвертация `.docx → .md` (через Pandoc с fallback на python-docx).
- Применение пользовательских правок (review/feedback) к итоговому файлу со сквозной нумерацией плейсхолдеров.
- Admin UI: счётчики, просмотр feedback, запуск дообучения `opf train`, утверждение/отклонение правил.
- Два режима работы: `mock` (regex-эвристика) и `subprocess` (реальный `opf`).

### Out of Scope (MVP)

- Авторизация и роли (один пользователь).
- Очереди/Celery, горизонтальное масштабирование.
- Поддержка форматов кроме `.md`/`.docx` (PDF, RTF, изображения).
- Обратная замена (reverse map) — **намеренно**, ради приватности.
- Хранение истории загрузок дольше сессии.
- Docker / production-обвязка.
- Структурное логирование, метрики, observability.

## Success Metrics

- **Функционально:** end-to-end сценарий (upload → очистка → download) работает в `mock` без ошибок.
- **Корректность:** все 8 типов сущностей находятся и заменяются стабильно; сквозная нумерация сохраняется после правок.
- **Тестируемость:** `make check` (ruff + mypy + pytest) проходит; coverage ≥ 70% (`make test-cov`); `make test-real` с реальной OPF-моделью проходит перед релизом.
- **Операционность:** `make dev` поднимает сервис одной командой; `make pre-release` — полный pre-release чек.

## Domain Glossary

- **PII (Personal Identifiable Information):** персональные данные — имя, контакт, адрес, дата рождения, идентификатор.
- **EntityType:** перечисление 8 типов PII (см. `backend/neironir/domain/entity_type.py`).
- **Placeholder:** шаблон замены, например `<PRIVATE_PERSON1>`. Нумерация сквозная в пределах одного документа.
- **Privacy filter:** локальная модель, заменяющая PII на плейсхолдеры (в проекте — `opf` из `openai/privacy-filter`).
- **Mock-режим:** regex-эвристика вместо реальной модели — для разработки и CI.
- **Subprocess-режим:** реальный вызов `opf` через CLI-subprocess.
- **Job:** единица обработки одного документа (upload → processing → completed/failed).
- **Feedback:** правки пользователя, внесённые в review-секции, которые могут быть применены к итоговому файлу.
- **Replacement / replacement map:** пары (исходный текст → плейсхолдер). **Не хранятся** — осознанное решение MVP.
