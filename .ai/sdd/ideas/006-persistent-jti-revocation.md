# Idea 006: Persistent jti revocation registry

**Проблема.** Реестр отозванных jti (admin-сессии, spec 007) живёт в памяти
процесса (`process-local`). При рестарте сервера все logout-ревокации
теряются: украденная session-cookie снова валидна до истечения TTL.

**Предложение.** Вынести revoked-jti в персистентное хранилище: MVP —
файл/append-log в `storage/` (загрузка при старте, дедуп по jti, чистка по
TTL); при масштабировании за пределы one-process — таблица в БД (SQLite →
PostgreSQL).

**Оценка усилия.** M: интерфейс revocation-store + файловая реализация +
тесты на рестарт-сценарий ~150 строк; миграция на БД позже, интерфейс уже
готов. Обратить внимание на запись ревокации до ответа клиенту на logout.
